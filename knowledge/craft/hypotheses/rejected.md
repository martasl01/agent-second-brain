# Rejected Hypotheses — Immune Memory (Content)

This file stores beliefs that were tested and proven wrong. Without it, the same false belief gets rediscovered and re-tested every few months. In the case study these are "false beliefs — things conventional wisdom says hurt but data shows don't."

**When to add:** when a hypothesis is rejected (see `index.md` criteria), move it here with the evidence that killed it. Never delete — archiving is cheap, re-testing is expensive.
**When to read:** at the start of any drafting task where a known false belief might resurface. Check this file proactively.

---

## Entry Format

```
### [HYP-ID] — [Short description of the belief]
**Was:** [The original hypothesis statement]
**Evidence against:** [What disproved it]
**Key learning:** [What the failure taught — often more valuable than the hypothesis]
**Replaced by:** [If a better rule emerged, link it]
**Rejected:** [DATE]
```

### HYP-000 — [ILLUSTRATIVE STARTER] "Posting more often grows the account faster"
**Was:** Increasing posting frequency (volume) is the primary driver of impressions growth.
**Evidence against:** Illustrative only — no own data logged yet. The case study explicitly attributes its growth to *a system that compounds*, **not** to writing more ("Not from writing more. Not from better prompts. From building a system that compounds.").
**Key learning:** Volume is a vanity lever; compounding quality (templates, hypotheses, performance log feeding back into drafts) is the real driver. Reframe "post more" as "iterate more per post" (10+ iterations, see `../writing-techniques.md`).
**Replaced by:** the system architecture itself (`CLAUDE.md` + this knowledge base).
